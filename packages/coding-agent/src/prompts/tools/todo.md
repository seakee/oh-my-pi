`todo` never takes a turn of its own: emit it in the same response as your next real tool call (parallel tool calls), with `init` beside the first read or action and `done`/`start` beside the next action or check. A response whose only call is `todo` wastes a full model round trip.
Tasks are identified by their verbatim content, never by generated IDs such as task-1. Task and phase names must be unique and stable; when text is lost, view it rather than guessing.
Before work, initialize for 3+ steps, requested task sets, or new instructions. List every user item separately (phased, numbered, bulleted, or N items), and never omit one or just remember the leftovers.
After a successful mutation: with no active task, the earliest pending one starts in phase order; with several active, only the earliest stays. A blocked task never starts automatically, and unblocking returns it to pending. Completing tasks out of order may rewind the pointer but never reopens completed work. Mark a task done immediately, following phase order.
External waits (user, agent, service): blocking with an optional reason suppresses the stop reminder and starts the next pending task. Unblock it when it becomes actionable, and append a clearing task for a blocker an agent can act on.
