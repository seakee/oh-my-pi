Describe the behavior and get back the files and line ranges that implement it. Start here when you do not know where something lives; known strings or regexes belong to `grep`, and known names to `glob`.
`query` is plain language, not a regex; a quoted phrase matches as a whole. `grep_keywords` holds likely verbatim terms, or `[]` when unsure.
`path` is one directory or file, given as a host path or an internal URL (`omp://`, `omp://<file>.md`, `skill://<name>`, `local://…`); omit it to search from the workspace root. Scope the subsystem you already know about, and batch related questions. The search reads live files with no index and accepts no `:start-end` selector, since it judges whole files.
Hits come strongest first as `path:start-end score snippet`, relative to the workspace (or under the URL scope); read the ranges it returns. Scores are absolute, comparable 0–1 probabilities: below about 0.4 the evidence is weak, so widen the query or try `grep` before concluding something is absent.
