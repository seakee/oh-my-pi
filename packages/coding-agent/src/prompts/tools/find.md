Describe the behavior and get back the implementing files and line ranges. Start here when you do not know where something lives; known strings, regexes, or symbols belong to `grep`, and file names belong to `glob`.
`query` is plain language, not a regex; a quoted phrase matches as a whole. `grep_keywords` holds likely verbatim terms, or `[]` when unsure.
`path` is one directory or file, given as a host path or a session URI (`skill://<name>`, `local://…`); omit it to search from the workspace root. Scope a known subsystem and batch related questions. The search reads live files with no index and accepts no `:start-end` selector, since it evaluates whole files.
Hits are returned strongest first as `path:start-end score snippet`, relative to the workspace (or under the URL scope); read the returned ranges. Scores are absolute, comparable 0–1 probabilities: below about 0.4 the evidence is weak, so widen the query or use `grep` before concluding something is absent.
